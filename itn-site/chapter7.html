1Chapter overviewFrom the course PDFs

Chapter 7 is about how applications get their data, intact and in order — or fast, without guarantees. It opens with the transport layer's role: temporary sessions between applications, tracking conversations, segmentation and reassembly, and identifying the right application. It covers multiplexing (many conversations interleaved, distinguished by header + port numbers), the reliability trade-off (acknowledged delivery costs overhead), then the two protocols themselves: TCP (RFC 793 — connection-oriented, reliable, ordered, flow-controlled, stateful) versus UDP (RFC 768 — connectionless, unreliable, stateless, low overhead). Section 7.2 walks through the three-way handshake, session termination, sequence numbers, acknowledgements, window size and UDP datagram reassembly — and closes with the layer's three main services: multiplexing, segmentation/reassembly and error checking.

Learning objectives

  • State the transport layer's responsibilities and its three main services (slides 3–8, summary).
  • Explain conversation multiplexing and how port numbers separate applications (slides 5–12).
  • Compare TCP and UDP feature by feature and match real applications to each (slides 9–13).
  • Describe how a TCP session is established (three-way handshake) and terminated (slides 17–22).
  • Explain reliability mechanisms: sequence numbers, acknowledgements, window size and reassembly (slides 23–25).

Most important concepts

  • Temporary sessions — the transport layer establishes sessions between applications and delivers data between them.
  • Multiplexing & ports — many simultaneous conversations interleaved; ports identify the application.
  • Segmentation & reassembly — split data into segments with headers; rebuild streams at the destination.
  • Reliability trade-off — acknowledged delivery vs overhead; the application developer chooses.
  • TCP vs UDP — stateful/reliable/ordered vs stateless/connectionless/low overhead.
  • Flow control via window size — how much may be sent before an acknowledgement is required.

2Key definitionsFrom the course PDFs

Transport layer

Responsible for establishing a temporary communication session between two applications and delivering data between them; TCP/IP uses TCP and UDP. slide 3

Multiplexingconversation multiplexing

Enabling many communications from many users to be interleaved on the same network at the same time; each segment gets a header to identify it so both sending and receiving work with multiple applications running. slide 5

Segmentation

The transport layer dividing application data into manageable pieces and adding a header for delivery; the destination reassembles them into application data streams. slide 3

Port numbers

TCP and UDP use port numbers to differentiate between applications — the header field that gets each segment to the right application. slide 11

TCPTransmission Control Protocol

RFC 793; connection-oriented (creates a session), reliable delivery (retransmits lost/corrupt data), ordered data reconstruction, flow control, stateful (tracks the session). slide 9

UDPUser Datagram Protocol

RFC 768; connectionless, unreliable delivery, no ordered reconstruction, no flow control, stateless. Used by DNS, video streaming, VoIP. slide 10

Connection-oriented vs connectionless

Connection-oriented (TCP) creates a session first; connectionless (UDP) sends without establishing one. slide 9

Stateful vs stateless

TCP is stateful — it tracks the session; UDP is stateless — it keeps no session state. slide 10

Flow control

Regulating the amount of data transmitted — TCP feature implemented with window size: the amount of data a source may transmit before an acknowledgement must be received. slide 24

Sequence number

Used to reassemble segments into their original order (ordered delivery). slide 23

Acknowledgement number

Used together with the sequence number to confirm receipt of data. slide 24

Window size

The amount of data a source can transmit before an acknowledgement must be received. slide 24

Three-way handshake

TCP's session-establishment process: confirm the destination device is present, verify it has an active service accepting requests on the intended port, and inform it that the source intends to establish a session on that port. slide 17

Netstat

A tool used to examine TCP connections that are open and running on a networked host. slide 14

RFCRequest for Comments

The documents defining protocols — TCP is defined in RFC 793, UDP in RFC 768. slide 9

3Concept explanationsStudy note

The reliability trade-off in one sentence slide 8

Reliable delivery 'ensures all data arrives' using acknowledgements and retransmission — but 'makes larger demands on the network, more overhead'. UDP gives 'just the basic functions for delivery — no reliability' with less overhead. There is a trade-off between the value of reliability and the burden it places on the network, so application developers choose per application.

Example: File transfer needs every byte (TCP); a live voice call needs low delay more than perfect loss (UDP).

Why UDP still exists (and wins sometimes) slide 13

UDP is simple, connectionless and stateless — for apps that can tolerate small loss or cannot tolerate delay. The chapter lists: DNS, SNMP, DHCP, TFTP, IP telephony/VoIP and online games (plus video streaming from the UDP slide).

Example: In VoIP, a retransmitted voice packet arriving late is useless — dropping it and moving on beats waiting.

What the three-way handshake is checking slide 17

Before data flows, TCP must: (1) establish the destination device is present on the network; (2) verify it has an active service accepting requests on the destination port the client intends to use; (3) inform it that the source intends to establish a session on that port. Only then is the session up — and TCP, being stateful, tracks it.

Example: Opening a web session: the client must confirm something is actually listening on the server's port before sending the request.

How ordered, confirmed delivery works slide 24

Sequence numbers reassemble segments into original order even if they arrive shuffled. Sequence + acknowledgement numbers are used together to confirm receipt. Window size paces the sender: that much data may be in flight before an ACK must come back — flow control in practice.

Example: Window size 3 segments → send 3, wait for ACK, then send more — the receiver never gets overwhelmed.

Multiplexing: how two users' downloads don't mix slide 5

Many conversations are interleaved on the network simultaneously. Each segment carries a header identifying it (ports) so the receiving host can hand each stream to the correct application — the summary describes ports as a 'tunnel' from the transport layer to the right application.

Example: Your browser and music stream run at once: different ports route each stream back to its own application.

Segmentation from the layer's own perspective slide 26

The transport layer divides data from the application into segments, adds a header to identify and manage each segment, uses that header to reassemble them, and passes the result to the correct application — the chapter calls these the layer's three main services together with multiplexing and error checking.

Example: A large file arrives as many segments; sequence numbers rebuild it byte-for-byte before the application sees it.

Technical terms are kept exactly as the course uses them; the plain-language wording and examples are supplementary study notes.

Answer: A — Multiplexing, segmentation and reassembly, and error checking

Why: The chapter summary states these three main services and explains dividing data into segments, adding headers, reassembling and passing data to the correct application.

Show answer & explanation

Answer: True

Why: TCP slide (9): 'Stateful protocol — tracks the session'; UDP slide (10): 'Stateless protocol'.

Multiple choiceQ3. A game developer needs minimal delay and can tolerate losing an occasional packet. Which protocol fits, and why?

  • A. UDP — connectionless, no flow control, less overhead
  • B. TCP — retransmission guarantees nothing is lost
  • C. TCP — because games need ordered delivery above all
  • D. Either — the chapter says the protocols are interchangeable
Show answer & explanation

Answer: A — UDP

Why: UDP is for applications that 'can tolerate small loss of data' and 'cannot tolerate delay' — online games are listed as UDP users (slides 10, 13).

Short answerQ4. State the three purposes of TCP session establishment listed in the chapter.

Show answer & explanation

Answer: 1) Establish the destination device is present on the network; 2) verify it has an active service accepting requests on the destination port the client intends to use; 3) inform the destination that the source intends to establish a session on that port.

Why: Slide 17 lists these three bullet points for connection establishment and termination.

Short answerQ5. What are sequence numbers used for, and what do sequence and acknowledgement numbers do together?

Show answer & explanation

Answer: Sequence numbers reassemble segments into their original order; together with acknowledgement numbers they confirm receipt of data.

Why: Slides 23 and 24 state both functions.

Multiple choiceQ6. Window size refers to:

  • A. The amount of data a source can transmit before an acknowledgement must be received
  • B. The maximum size of a UDP datagram
  • C. The number of applications on a host
  • D. The time a session stays open
Show answer & explanation

Answer: A — data allowed in flight before an ACK is required

Why: Slide 24 defines window size exactly this way — it is TCP's flow-control mechanism.

ExplanationQ7. Why might an application designer deliberately choose UDP even though it is called 'unreliable'? Support your answer with examples from the chapter.

Show answer & explanation

Answer: Because reliability costs overhead, and some applications value low delay or low overhead over perfect delivery. The chapter lists DNS, SNMP, DHCP, TFTP, VoIP/IP telephony and online games as UDP users, and notes UDP serves apps that can tolerate small loss or cannot tolerate delay — plus there is an explicit trade-off between the value of reliability and the burden it places on the network.

Why: Slides 8, 10 and 13 give the trade-off and the application lists.

True or falseQ8. Port numbers allow TCP and UDP to differentiate between applications, and netstat can show open TCP connections on a host.

Show answer & explanation

Answer: True

Why: Slide 11 (ports differentiate applications) and slide 14 (netstat examines open, running TCP connections).

7Common misunderstandingsStudy note

"UDP is unreliable, so it's bad"

Unreliable is a design choice for low overhead/low delay. The chapter lists DNS, VoIP, streaming and games as deliberate UDP users and frames it as a trade-off, not a defect (slides 8, 13).

Ports identify devices

Ports differentiate applications on hosts — the header gets each segment to the right application ('tunnel' to the application — summary, slide 26).

Multiplexing means one conversation at a time

It is the opposite: many users' communications are interleaved on the same network at the same time; headers/ports keep them apart (slide 5).

The handshake moves data

The three-way handshake establishes and verifies the session (device present, service listening, intent declared) — it is setup, not the data transfer itself (slide 17).

8Quick revision (2–5 minutes)Study note

  • Role: temporary sessions between applications; three main services — multiplexing, segmentation & reassembly, error checking; ports tunnel data to the right application.
  • Multiplexing: many conversations interleaved; each segment's header identifies it.
  • TCP (RFC 793): connection-oriented, reliable (retransmit lost/corrupt), ordered (sequence numbers), flow control (window size), stateful — more overhead.
  • UDP (RFC 768): connectionless, unreliable, unordered, no flow control, stateless — less overhead; DNS, SNMP, DHCP, TFTP, VoIP, video, games.
  • Handshake: confirm destination present → service active on target port → session intent declared; session later terminated the same way.
  • Reliability internals: seq# = original order; seq#+ack# = confirm receipt; window size = bytes allowed before an ACK must return.
  • Tools: netstat shows open TCP connections. Choose by trade-off: value of reliability vs burden on the network.

Role of the Transport Layer

The transport layer is responsible for establishing a temporary

communication session between two applications and delivering data

between them.

TCP/IP uses two protocols to achieve this:

  • Transmission Control Protocol (TCP)
  • User Datagram Protocol (UDP)

Primary Responsibilities of Transport Layer Protocols

  • Tracking the individual communication between applications on the source and destination hosts
  • Segmenting data for manageability and reassembling segmented data into streams of application data at the destination
  • Identifying the proper application for each communication stream

Chapter 7: Summary

In this chapter, you learned:

  • The role of the transport layer is to provide three main services: multiplexing, segmentation and reassembly, and error checking. It does this by:
  • Dividing data received from an application into segments.
  • Adding a header to identify and manage each segment.
  • Using the header information to reassemble the segments back into application data.
  • Passing the assembled data to the correct application.
  • How TCP and UDP operate and which popular applications use each protocol.
  • Transport Layer functions are necessary to address issues in QoS and security in networks.
  • Ports provide a “tunnel” for data to get from the transport layer to the appropriate application at the destination.
