1Chapter overviewFrom the course PDFs

Chapter 5 is the Ethernet deep dive. It places Ethernet in the IEEE 802.2/802.3 standards, splits the data link layer into LLC (control information, upper/lower layer communication) and MAC (frame encapsulation + media access, implemented in the NIC), and works through frame mechanics: delimiting, MAC addressing, CRC error detection, frame sizes (64–1518 bytes) and unicast/multicast/broadcast communication. Section 5.2 covers ARP — resolving IPv4 addresses to MAC addresses, building ARP tables, local vs remote (gateway) resolution and cache expiry. Section 5.3 covers LAN switches — MAC-based forwarding/filtering, collision domains, cut-through switching, buffering — and finishes with Layer 3 switching (SVIs, routed ports, EtherChannel).

Learning objectives

  • Explain the LLC and MAC sublayers and the MAC sublayer's two responsibilities (slides 2–8).
  • Describe Ethernet addressing: 48-bit MAC addresses, OUI rules, frame processing and frame size limits (slides 9–11).
  • Distinguish unicast, multicast and broadcast communication and give the multicast ranges (slides 12–15).
  • Describe ARP's two functions, its operation on local and remote networks, and how ARP table entries expire (slides 17–22).
  • Explain how switches make forwarding decisions and compare Layer 2 with Layer 3 switching (slides 24–34).

Most important concepts

  • LLC + MAC — one protocol-facing, one media-facing sublayer of Layer 2.
  • Frame encapsulation — header (addresses) + payload + trailer (CRC).
  • MAC addresses — 48-bit, 12 hex digits, OUI + unique NIC identity.
  • ARP — IPv4 → MAC resolution, cached in an ARP table.
  • Switching — MAC-address-table-based forwarding/filtering; collision domains per port.
  • Layer 3 switching — SVIs, routed ports, EtherChannel for inter-subnet work.

2Key definitionsFrom the course PDFs

Ethernet

One of the most widely used LAN technologies; operates in the data link and physical layers; a family defined by IEEE 802.2 and 802.3; supports 10 / 100 / 1000 / 10,000 / 40,000 / 100,000 Mbps (100 Gbps). slide 2

LLCLogical Link Control

Upper data link sublayer: handles communication between upper and lower layers and takes network protocol data, adding control information to help deliver the packet to the destination. slide 4

MAC sublayerMedia Access Control

Lower data link sublayer, implemented in hardware (NIC), with two primary responsibilities: data encapsulation and media access control. slide 4

Data encapsulation (MAC)

Frame assembly before transmission and disassembly on reception: the MAC layer adds a header and trailer around the network layer PDU. slide 5

Frame delimiting

Identifying the group of bits that make up a frame and synchronising transmitting and receiving nodes. slide 5

CRCCyclic Redundancy Check

Error-detection value in each Ethernet frame's trailer, covering the frame contents. slide 5

MAC address

A 48-bit binary value expressed as 12 hexadecimal digits; the physical address added to Ethernet headers so frames reach the right node. slide 9

OUIOrganizationally Unique Identifier

The vendor's assigned identifier that IEEE requires as the first 3 bytes of every MAC address; the last 3 bytes must be unique for all addresses with that OUI. slide 9

Runt frame (collision fragment)

An Ethernet frame shorter than the 64-byte minimum — dropped by the receiving device. slide 11

Unicast / broadcast / multicast

Unicast = delivered to the single NIC whose MAC matches the frame's destination; broadcast = a Layer 2 broadcast to all devices (as ARP requests are); multicast = a special group value — MACs beginning 01-00-5E, with IPv4 multicast addresses 224.0.0.0–239.255.255.255. slide 14

ARPAddress Resolution Protocol

Provides two basic functions: resolving IPv4 addresses to MAC addresses and maintaining a table of those mappings. slide 17

ARP table (ARP cache)

Mappings of IPv4 ↔ MAC learned as frames arrive (source IP and MAC recorded); entries are removed by a cache timer after unused periods, or manually with commands. slide 21

Switch

Intermediary device that connects end devices, performs switching and filtering based only on the MAC address, builds a MAC address table for forwarding decisions, and depends on routers to pass data between IP subnetworks. slide 24

Cut-through switching

Forwarding method with the lowest level of latency: the switch forwards a packet immediately after reading the address — most network errors and collisions occur in the first 64 bytes, which is what it has seen. slide 29

SVISwitch Virtual Interface

A logical interface on a Layer 3 switch associated with a VLAN. slide 33

Routed port

A physical port on a Layer 3 switch configured to act as a router port. slide 33

Layer 3 EtherChannel

A logical interface associated with a bundle of routed ports (port aggregation). slide 33

CSMACarrier Sense Multiple Access

Ethernet's media-sharing method: first detect whether the media carries a signal; if none, transmit; simultaneous transmissions collide and corrupt the data. slide 7

3Concept explanationsStudy note

What the MAC sublayer actually does slide 5

Two jobs: (1) Data encapsulation — assemble frames before transmission and disassemble on reception; add header (delimiting, physical addressing) and trailer (CRC error detection) around the Layer 3 PDU. (2) Media access control — place frames onto media and remove them; if several devices transmit at once they collide, so Ethernet uses CSMA to control sharing.

Example: The header carries source/destination MACs; the trailer's CRC lets the receiver detect corruption before accepting the frame.

How a NIC decides what to do with a frame slide 10

Every incoming frame's destination MAC is compared with the device's physical MAC stored in the NIC's RAM. No match → discard. Match → pass the frame up the OSI layers for de-encapsulation and processing.

Example: A switch-port mirror shows broadcast frames hitting every NIC, but only the intended recipient keeps one — everyone else's NIC discarded it.

ARP, step by step (local network) slide 19

A node needs the destination MAC for an IPv4 address on its Ethernet link. It sends a Layer 2 broadcast; the node whose IP matches the request replies with its MAC. Meanwhile nodes record source IP/MAC pairs from passing frames into the ARP table. If nobody replies, the packet is dropped because a frame cannot be created.

Example: PC1 pinging 192.168.1.5 for the first time broadcasts; the reply caches 192.168.1.5 ↔ its MAC for all later frames.

ARP when the destination is NOT local slide 20

If the destination IPv4 host is on the local network, frames use its MAC directly. If it is not, the source must send to its gateway: it uses ARP to learn the MAC of the router interface serving as the gateway (requesting it if the entry isn't already cached) and addresses frames there.

Example: Reaching a server on another subnet: your PC ARPs for the default gateway's MAC, not the server's.

Why switches beat hubs (collision domains) slide 26

The chapter's collision-domain slide contrasts one collision domain with five — each switch port isolates its own collision domain, and the summary notes that replacing hubs with switches reduced the probability of frame collisions on half-duplex links.

Example: Five PCs on one hub share a single collision domain; on a switch each PC gets its own.

Cut-through: speed over verification slide 29

Cut-through forwards as soon as the address is read — lowest latency — and relies on the observation that most errors/collisions occur in the first 64 bytes. The trade-off (implied by that fact): corrupted frames later in the payload are forwarded rather than filtered.

Example: Latency-sensitive fabrics prefer cut-through; error-sensitive paths may prefer full-frame checking (the other method shown in the slide figure).

Physical vs logical address — the person analogy slide 15

The MAC address never changes, is assigned to the NIC ('physically'), like a person's name. The IP address depends on where the host is located, is assigned logically by an administrator, like a person's address. Both are required to communicate — just as both name and address are needed to send a letter.

Example: Move your laptop to another network: its MAC (name) stays, its IP (address) changes.

5Important factsFrom the course PDFs

  • Ethernet = most widely used LAN technology; standards define both Layer 2 protocols and Layer 1 technologies (IEEE 802.2/802.3); bandwidths up to 100,000 Mbps (100 Gbps). slide 2
  • MAC sublayer responsibilities: data encapsulation (frame assembly/disassembly, header+trailer) and media access control (placement/removal of frames on media). slide 5
  • Header carries the physical (MAC) address; trailer carries a CRC for error detection. slide 5
  • MAC address: 48-bit / 12 hex digits; IEEE rule: OUI = first 3 bytes of the vendor; last 3 bytes unique per vendor. slide 9
  • Example MAC notations: 00-05-9A-3C-78-00, 00:05:9A:3C:78:00, 0005.9A3C.7800. slide 10
  • NIC behaviour: destination MAC mismatch → discard; match → pass up the OSI layers for de-encapsulation. slide 10
  • Ethernet II / IEEE 802.3: minimum frame 64 bytes, maximum 1518 bytes; <64 = 'collision fragment' / runt; out-of-size frames are dropped. slide 11
  • Multicast MACs begin 01-00-5E; IPv4 multicast range 224.0.0.0 – 239.255.255.255. slide 14
  • ARP functions: resolve IPv4 → MAC and maintain the mapping table; requests are Layer 2 broadcasts; no reply → packet dropped (no frame can be created). slide 19
  • Remote destination → ARP for the gateway router interface's MAC; ARP cache entries age out via a timer and can be removed manually. slide 21
  • Switches: forward/filter on MAC only, build a MAC address table, and depend on routers to pass data between IP subnetworks. slide 24
  • Cut-through = lowest latency — forwards right after reading the address; most errors/collisions occur in the first 64 bytes. slide 29
  • Layer 3 interface types: SVI (logical per VLAN), routed port (physical, acts as router port), Layer 3 EtherChannel (bundle of routed ports). slide 33
  • Summary: replacing hubs with switches reduced collision probability on half-duplex links; Ethernet uses ARP to map destinations against known network-layer addresses. slide 35

Multiple choiceQ1. What are the minimum and maximum Ethernet frame sizes, and what is a frame shorter than the minimum called?

  • A. 64 and 1518 bytes; a runt (collision fragment)
  • B. 64 and 512 bytes; a jabber
  • C. 46 and 1500 bytes; a giant
  • D. 128 and 1518 bytes; a fragment
Show answer & explanation

Answer: A — 64 and 1518 bytes; runt / collision fragment

Why: Slide 11: Ethernet II and IEEE 802.3 define minimum 64 bytes, maximum 1518; under 64 is a 'collision fragment' or 'runt frame', and out-of-size frames are dropped.

True or falseQ2. IEEE requires a vendor to place its assigned OUI in the LAST three bytes of every MAC address it issues.

Show answer & explanation

Answer: False

Why: The OUI must be the first 3 bytes; the last 3 bytes must be unique within that OUI (slide 9).

Short answerQ3. State ARP's two basic functions.

Show answer & explanation

Answer: 1) Resolving IPv4 addresses to MAC addresses; 2) maintaining a table of those mappings.

Why: Slide 17 lists exactly these two functions.

Multiple choiceQ4. Your PC wants to send a frame to a host on a different network. Which MAC address does ARP resolve?

  • A. The MAC of the router interface serving as the gateway
  • B. The MAC of the remote host
  • C. The MAC of the DNS server
  • D. No MAC — remote hosts don't use MAC addresses
Show answer & explanation

Answer: A — the gateway router interface's MAC

Why: Slide 20: if the destination is not on the local network, the source uses ARP to determine the MAC of the router interface serving as the gateway (or broadcasts for it if not cached).

True or falseQ5. An Ethernet switch performs switching and filtering based only on MAC addresses and relies on routers to pass traffic between IP subnetworks.

Show answer & explanation

Answer: True

Why: Slide 24 states both points directly.

Short answerQ6. Give the multicast MAC prefix and the IPv4 multicast address range.

Show answer & explanation

Answer: MAC prefix 01-00-5E; IPv4 multicast range 224.0.0.0 to 239.255.255.255.

Why: Slide 14 gives both values.

ExplanationQ7. Explain what happens when a frame arrives at a NIC whose destination MAC does not match, and what happens when it does.

Show answer & explanation

Answer: No match: the device discards the frame. Match with the device's physical MAC stored in RAM: the NIC passes the frame up the OSI layers, where de-encapsulation takes place.

Why: Slide 10 walks through exactly this two-branch decision.

Multiple choiceQ8. Which statement about cut-through switching is correct?

  • A. Lowest latency — forwards right after reading the address
  • B. Highest latency — waits for the full frame and CRC check
  • C. Filters frames by IP address
  • D. Only used on Layer 3 switch routed ports
Show answer & explanation

Answer: A — lowest latency, immediate forwarding after the address

Why: Slide 29: 'Lowest level of latency — immediately forwards a packet after reading the address', justified by most errors/collisions occurring in the first 64 bytes.

7Common misunderstandingsStudy note

MAC address vs IP address

MAC = physical, permanent, NIC-assigned (like a person's name); IP = logical, location-based, administrator-assigned (like a person's address). Communication needs both (slide 15).

A switch sends to everyone (broadcast)

Switches forward and filter based on the MAC address table (slide 24). Broadcasts happen when a protocol sends them — e.g. ARP requests — or to an unknown destination, not because switches are hubs.

ARP works the same for local and remote destinations

Local: ARP resolves the destination host's MAC. Remote: frames go to the gateway router interface's MAC instead — a different ARP target (slide 20).

Small frames are fine

Anything under 64 bytes is a runt/collision fragment and is dropped; over 1518 is also dropped (slide 11).

Switching happened at Layer 3

Basic switching/filtering is MAC-only (Layer 2). Inter-subnet traffic needs routers — or a Layer 3 switch using SVIs, routed ports or EtherChannels (slides 24, 32–33).

8Quick revision (2–5 minutes)Study note

  • Ethernet = IEEE 802.2 (LLC) + 802.3 (MAC/physical), most used LAN tech, up to 100 Gbps; operates at data link + physical layers.
  • MAC sublayer: encapsulation (header = delimiting + MAC addressing; trailer = CRC) and media access (CSMA: sense carrier → transmit → collisions possible).
  • Addresses: 48-bit / 12 hex digits; OUI = first 3 bytes (vendor), last 3 unique. NIC: mismatch → discard; match → pass up. Notation examples: 00-05-9A-3C-78-00 / 0005.9A3C.7800.
  • Frames: 64–1518 bytes (runt = <64, dropped). Unicast (one NIC), broadcast (all — like ARP requests), multicast (01-00-5E; 224.0.0.0–239.255.255.255).
  • ARP: resolve IPv4→MAC + maintain table; L2 broadcast, matching host replies, no reply → drop; remote targets = gateway router MAC; cache times out or cleared manually.
  • Switches: MAC-table decisions, filter/forward by MAC, one collision domain per port, cut-through = lowest latency; depend on routers between subnets.
  • Layer 3 switching: SVI (logical/VLAN), routed port (physical as router), EtherChannel (bundle). MAC = physical (name), IP = logical (address) — both needed.

Ethernet Operation

MAC Sublayer

Data encapsulation

  • Frame assembly before transmission and frame disassembly upon reception of a frame.
  • MAC layer adds a header and trailer to the network layer (Protocol Data Unit) PDU.

Provides three primary functions:

  • Frame delimiting – Identifies a group of bits that make up a frame, synchronization between the transmitting and receiving nodes.
  • Addressing – Each Ethernet header added in the frame contains the physical address (MAC address) that enables a frame to be delivered to a destination node.
  • Error detection – Each Ethernet frame contains a trailer with a cyclic redundancy check (CRC) of the frame contents.

Slide 19
ARP

ARP Functions/Operation

ARP Table

  • Used to find the data link layer address that is mapped to the destination IPv4 address.
  • As a node receives frames from the media, it records the source IP and MAC address as a mapping in the ARP table.

ARP Request

  • Layer 2 broadcast to all devices on the Ethernet LAN.
  • The node that matches the IP address in the broadcast will reply.
  • If no device responds to the ARP request, the packet is dropped because a frame cannot be created.

Note: Static map entries can be entered in an ARP table, but this is

rarely done.

Chapter 5 Summary

1 slide
Slide 35
Chapter 5

Summary

  • Ethernet is the most widely used LAN technology used today.
  • Ethernet standards define both the Layer 2 protocols and the Layer 1 technologies.
  • The Ethernet frame structure adds headers and trailers around the Layer 3 PDU to encapsulate the message being sent.
  • As an implementation of the IEEE 802.2/3 standards, the Ethernet frame provides MAC addressing and error checking.
  • Replacing hubs with switches in the local network has reduced the probability of frame collisions in half-duplex links.
  • The Layer 2 addressing provided by Ethernet supports unicast, multicast, and broadcast communications.
  • Ethernet uses the Address Resolution Protocol to determine the MAC addresses of destinations and map them against known Network layer addresses.
