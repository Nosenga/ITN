1Chapter overviewFrom the course PDFs

Chapter 10 covers the top of the stack: the application layer as the interface between user programs and the network, plus the presentation layer (coding, compression, encryption) and session layer (managing dialogs) whose functionality modern applications absorb. It compares peer-to-peer with client-server models, then tours the well-known protocols: HTTP/HTTPS (web, GET/POST/PUT), SMTP/POP/IMAP (sending vs retrieving mail — and how POP and IMAP differ), DNS (name → numeric address, nslookup), DHCP (dynamic addresses from a leased pool) and FTP (two connections: commands/replies + file transfer), and ends with the encapsulation checklist for getting data through the internetwork.

Learning objectives

  • Explain what the application layer provides and how it relates to presentation and session functions (slides 2–5).
  • Compare the peer-to-peer and client-server communication models (slides 6–9).
  • Describe HTTP(S) and the URL/GET flow for web retrieval (slides 11–13).
  • Compare email protocols — SMTP for transfer, POP and IMAP for retrieval (with ports) (slides 14–17).
  • Explain DNS, nslookup, DHCP leasing and FTP's two connections (slides 18–24).

Most important concepts

  • Application layer — interface between user applications and the underlying network; protocols exchange data between programs.
  • Apps vs services vs protocols — programs you use vs background connectors vs agreed rules.
  • Presentation + session — coding/compression/encryption and dialog management, usually folded into the app.
  • P2P vs client-server — equal peers with per-request roles vs dedicated service providers.
  • Protocol portfolio — HTTP(S), SMTP/POP/IMAP, DNS, DHCP, FTP.
  • Address/name services — DNS resolves names; DHCP leases addresses from pools.

2Key definitionsFrom the course PDFs

Application layer

Provides the interface between the applications we use to communicate and the underlying network; application layer protocols exchange data between programs running on source and destination hosts. slide 2

Application vs service vs protocol (from the summary)

Applications = programs the user interacts with that initiate data transfer on request; services = background programs connecting the application layer to lower layers; protocols = agreed rules/processes letting services on one device exchange data with a range of devices. slide 26

Presentation layer

Coding and conversion of application data, data compression, and encryption for transmission / decryption on receipt; also coding standards for video and graphics. slide 4

Session layer

Functions that create and maintain dialogs between source and destination applications — initiating dialogs, keeping them active and restarting sessions. slide 4

Peer-to-peer (P2P)

Both devices are equal in the communication; client/server roles are set per request; in P2P applications both act as client and server at the same time. slide 6

Client-server model

One side provides services (server), the other requests them (client) — the model web browsers and e-mail clients assume (client/server basics from Chapter 1, slide 6). slide 8

HTTPHypertext Transfer Protocol

Used to publish and retrieve HTML pages; specifies a request/response protocol; common messages: GET (client request for data), POST and PUT (send messages that upload data to the web server). slide 13

URL parts (as the browser sees them)

http = the protocol/scheme; www.cisco.com = the server name (resolved to a numeric address); index.html = the specific file requested — then a GET request is sent and the server returns HTML for the browser to format. slide 12

SMTPSimple Mail Transfer Protocol

Sends (transfers) e-mail; SMTP processes must run on both client and server; uses port 25. slide 15

POP / POP3Post Office Protocol

Lets a workstation retrieve mail from a mail server — mail is downloaded to the client and deleted on the server; uses port 110; desirable for ISPs because it relieves them of storing large mail volumes. slide 15

IMAPInternet Message Access Protocol

Another retrieval protocol: copies of messages are downloaded while originals stay on the server until manually deleted — the contrast with POP. slide 17

DNSDomain Name Service

Resolves a URL/host name to its numeric network address. slide 18

TLDtop-level domain

The suffix level of DNS names (the hierarchy slide gives examples such as organization/industry endings — shown as a figure). slide 19

nslookup

Operating-system utility to manually query name servers to resolve a host name — used to troubleshoot name resolution and verify name-server status. slide 20

DHCPDynamic Host Configuration Protocol

Lets a host obtain an IP address dynamically: the DHCP server chooses one from a configured range (pool) and leases it for a set period; used for general-purpose end-user hosts. slide 21

FTPFile Transfer Protocol

Data transfers between client and server; requires two connections — one for commands and replies, one for the actual file transfer. slide 24

MDAmail delivery agent (in the mail flow)

The chapter notes mail transfer components can also solve issues like virus scanning and spam filtering. slide 16

3Concept explanationsStudy note

Where presentation and session went slide 3

Most applications (web browsers using HTTP, e-mail clients using SMTP/POP) incorporate the functionality of the application, presentation and session layers. So the 'layers' still exist as functions — coding/conversion, compression, encryption, dialog management — but live inside the software you run.

Example: When your browser encrypts a connection and resumes a session after a brief drop, it is performing presentation and session work itself.

Web page fetch, step by step (the chapter's flow) slide 12

1) Browser interprets the URL: scheme http, server name, file name. 2) The server name is resolved to a numeric address. 3) Using HTTP requirements, a GET request is sent. 4) The server sends the page's HTML code. 5) The browser deciphers the HTML and formats the page.

Example: Every page load you have ever done repeats these five steps.

The three e-mail jobs — and the POP/IMAP split slide 17

SMTP transfers mail (both ends run SMTP; port 25). POP retrieves (port 110): download then delete on server — light storage burden, good for ISPs. IMAP also retrieves, but keeps originals on the server until manually deleted, with copies local — better for multi-device access. Retrieval is where POP and IMAP compete; SMTP is always the sender's transfer protocol.

Example: Check mail on two devices? IMAP keeps the master copy server-side; POP's download-and-delete would strip it after the first device.

DHCP leasing in plain language slide 21

A host needing an address contacts the DHCP server and requests one; the server picks from a configured pool and leases it for a set period. Lease = temporary, renewable ownership — which is why addresses can change, and why planned/static assignments belong in the addressing plan (Chapter 9).

Example: Laptop joins the office network: DHCP hands it an address from the pool for a few hours.

FTP's two-connection design slide 24

FTP needs two separate connections between client and server: one for commands and replies (control), one for the actual file transfer (data). Separating them lets control messages flow while bulk data moves.

Example: During a large upload you can still issue commands because they travel on the separate connection.

Getting data through the internetwork (the layer checklist) slide 25

The chapter's closing slide lists what travels at each step as data moves through the stack: code, compress, encrypt, segment (with port #, seq #) and add source & destination IP addresses and source & destination MAC addresses — the whole journey in one line, matching the encapsulation story of Chapter 3.

Example: One e-mail attachment touches presentation (encode/compress/encrypt), transport (port + sequence), network (IPs) and data link (MACs).

Technical terms are kept exactly as the course uses them; the plain-language wording and examples are supplementary study notes.

5Important factsFrom the course PDFs

  • Application layer = the interface between applications and the underlying network; protocols exchange data between programs on source and destination hosts. slide 2
  • Most applications incorporate application, presentation and session functionality; protocol families named: DNS, HTTP, DHCP, FTP; transfer/retrieval via SMTP, IMAP, POP. slide 3
  • Presentation: coding/conversion, compression, encryption/decryption; Session: create/maintain dialogs, keep them active, restart sessions. slide 4
  • Three everyday protocols: HTTP to browse the web, SMTP to send e-mail, POP to receive e-mail. slide 11
  • URL parts: scheme (http), server name, file name → GET → server returns HTML → browser formats the page. slide 12
  • HTTP messages: GET (request data); POST / PUT (upload data to the web server); request/response protocol. slide 13
  • SMTP: transfer mail, port 25, SMTP processes on both client and server; POP: retrieve, port 110, download-and-delete, ISP-friendly storage. slide 15
  • IMAP retrieves by keeping originals on the server until manually deleted; mail components can also do virus scanning and spam filtering. slide 17
  • DNS resolves URL names to numeric addresses; nslookup manually queries name servers to troubleshoot/verify status. slide 20
  • DHCP: request → server picks from a configured pool → lease for a set period; for general-purpose end-user hosts. slide 21
  • FTP needs two connections: commands/replies + file transfer. slide 24
  • End-to-end checklist: code, compress, encrypt segment, port #, seq #, source & destination IP addresses, source & destination MAC addresses. slide 25
  • Summary definitions: applications initiate transfer at user request; services are background connectors to lower layers; protocols are the agreed rules. slide 26

Multiple choiceQ1. What does the application layer provide, according to the chapter?

  • A. The interface between the applications we use and the underlying network
  • B. Encryption of all traffic on the wire
  • C. The physical signaling of bits
  • D. Routing between IP subnetworks
Show answer & explanation

Answer: A — the interface between applications and the underlying network

Why: Slide 2 states this directly and adds that application layer protocols exchange data between programs on the source and destination hosts.

True or falseQ2. With POP, mail is downloaded from the server to the client and deleted on the server, whereas IMAP keeps originals on the server until they are manually deleted.

Show answer & explanation

Answer: True

Why: Slides 15/17 (POP download-and-delete) and slide 17 (IMAP: 'Original messages are kept on the server until manually deleted').

Short answerQ3. Name the ports stated for SMTP and POP, and the job each protocol does.

Show answer & explanation

Answer: SMTP — transferring (sending) mail — port 25; POP — retrieving mail — port 110.

Why: Slide 15: SMTP 'uses port 25'; POP 'uses port 110'; both jobs described there.

Multiple choiceQ4. A URL is interpreted as http / www.cisco.com / index.html. What do the three parts mean, and what is sent next?

  • A. Protocol (scheme), server name, file name — then a GET request
  • B. Server name, protocol, file name — then a DNS response
  • C. Protocol, user name, password — then a POST request
  • D. File name, host, port — then an ARP request
Show answer & explanation

Answer: A — scheme, server name, file name → GET request

Why: Slide 12's numbered flow: browser interprets protocol/server/file, resolves the numeric address, sends a GET; the server returns HTML to format.

Short answerQ5. Why does FTP require two connections?

Show answer & explanation

Answer: One connection carries commands and replies; the other carries the actual file transfer.

Why: Slide 24: 'To successfully transfer data, FTP requires two connections between the client and the server, one for commands and replies, the other for the actual file transfer.'

ExplanationQ6. Explain what DHCP does when a host joins the network, using the terms 'pool' and 'lease'.

Show answer & explanation

Answer: The host requests an address; the DHCP server chooses one from a configured range of addresses called a pool and leases it to the host for a set period. DHCP is used for general-purpose hosts such as end-user devices.

Why: Slide 21 describes this sequence verbatim.

Multiple choiceQ7. Which pair correctly matches a protocol to its function in the chapter?

  • A. DNS — resolves a name to a numeric address; nslookup — manual queries to name servers
  • B. SMTP — retrieves mail; POP — sends mail
  • C. FTP — assigns IP addresses; DHCP — transfers files
  • D. HTTP — encrypts e-mail; IMAP — browses the web
Show answer & explanation

Answer: A — DNS resolves names; nslookup queries name servers

Why: Slides 18 and 20 give both functions; the others invert or misassign the protocols listed across slides 11–24.

ExplanationQ8. Using the presentation and session descriptions, show where 'compress, encrypt, keep the dialog alive' fits — and why the chapter says most applications incorporate all three layers.

Show answer & explanation

Answer: Compression and encryption/decryption are presentation functions; creating, maintaining and restarting dialogs is session work. Web browsers and e-mail clients fold application + presentation + session functionality into one program, so users experience them as part of the app rather than separate layers.

Why: Slides 3–4 provide the three layer descriptions and the 'incorporate' statement.

7Common misunderstandingsStudy note

The application layer is the application itself

The layer is the interface and the set of protocols (HTTP, SMTP, DNS…) exchanging data between programs; applications are the user-facing programs, services the background connectors (summary, slide 26).

POP and IMAP are interchangeable

Both retrieve, but POP deletes the server copy after download (port 110) while IMAP keeps originals on the server until manually deleted — different behaviour matters across devices (slides 15, 17).

DNS assigns addresses / DHCP resolves names

Opposite roles: DNS resolves names → numeric addresses; DHCP hands out the addresses themselves from a pool (slides 18, 21).

HTTPS is explained as 'HTTP plus a lock icon'

The chapter's HTTP/HTTPS slide describes HTTP's request/response and message types; it does not state HTTPS's security mechanism in the extractable text — treat HTTPS specifics as outside this deck (slide 13, gap note below).

Peer-to-peer means 'no clients or servers'

Roles still exist — they're simply set per request, with both devices acting as client and server at the same time (slides 6–7).

8Quick revision (2–5 minutes)Study note

  • Application layer: interface between user programs and the network; protocols move data between programs. Apps (user-facing) vs services (background) vs protocols (agreed rules).
  • Presentation: coding/conversion, compression, encryption/decryption. Session: dialogs — start, keep alive, restart. Modern apps fold both in.
  • Models: P2P = equal peers, roles per request, both roles at once; client-server = dedicated server vs requesting clients.
  • Web: URL = scheme + server + file → resolve → GET → HTML returned → browser formats. HTTP messages: GET, POST, PUT.
  • E-mail: SMTP sends (port 25) · POP retrieves, download-and-delete (port 110) · IMAP retrieves, originals stay on server. MDA can scan for viruses/spam.
  • DNS name → numeric address; nslookup queries/troubleshoots name servers. DHCP leases addresses from a pool to end-user hosts.
  • FTP: two connections — commands/replies + file transfer. End-to-end: code, compress, encrypt, segment (port#, seq#) + IP and MAC addresses.

  • DHCP allows a host to obtain an IP address dynamically.

  • DHCP used for general purpose hosts such as end user

devices, and static addressing is used for network devices such as gateways, switches, servers and printers.

Slide 26
Application Layer

Summary

  • Applications are computer programs with which the user interacts and which initiate the data transfer process at the user’s request.
  • Services are background programs that provide the connection between the application layer and the lower layers of the networking model.
  • Protocols provide a structure of agreed-upon rules and processes that ensure services running on one particular device can send and receive data from a range of different network devices.
  • HTTP supports the delivery of web pages to end devices.
  • SMTP, POP, and IMAP support sending and receiving email.
