9Common mistakes

  • Swapping address and mask fields, or typing a mask that does not match the address plan (both PCs must be 255.255.255.0).
  • Putting a default gateway on these PCs — this lab needs none; a gateway only matters when leaving the network course · Ch 6 slide 31.
  • Using different networks (e.g. 192.168.10.10 with 192.168.11.10) — that silently turns a local ping into a routed one that must fail here.
  • Connecting PC→PC directly instead of through the switch (works only by accident with Auto-MDIX course · Ch 5 slide 27 — build it the way the topology shows).
  • Forgetting to press the apply/save in the IP Configuration window, then pinging the old (empty) settings.
  • Reading one successful ping as 'the whole network is done' — the lab requires the return ping too (course: testing the interface assignment course · Ch 2 slide 38).

10Troubleshooting questions

Q1. PC0's ping to PC1 shows Request timed out the whole time. Give the first three things you would check, in order.

Show answer

1) Physical/link: are the cables Copper Straight-Through on working switch ports (green indicators) course · Ch 5 slide 24? 2) Addressing: do both PCs share one network and the same mask (192.168.10.x with 255.255.255.0)? 3) Conflicts/typos: is any address duplicated (course: IP address conflicts course · Ch 2 slide 37) or mistyped? Only after those does ARP/resolution matter course · Ch 5 slide 19.

Q2. Your first ping loses one reply but the next ping is 5/5. Why is this not a failure?

Show answer

The first echo may time out while the PC resolves the destination's MAC address into its ARP table course · Ch 5 slide 19. Once cached, every echo answers — the course's reference output is 5/5 course · Ch 6 slide 30. Assumption: Packet Tracer exhibits this ARP warm-up behaviour; the course does not describe it.

Q3. Why do PC0 and PC1 need no router and no default gateway, even though they are different devices?

Show answer

They are on the same network (192.168.10.0/24): the switch forwards frames between their ports using MAC addresses course · Ch 5 slide 24, and a gateway is only needed to leave the network — the course labels this exact case 'Default Gateway not needed' course · Ch 6 slide 31.

5Step-by-step configuration instructions

  1. Place and cable the devices. 2 PCs, 2 switches, 1 router. Copper straight-through: PC0→SW0, SW0→R1 G0/0, SW1→R1 G0/1, PC1→SW1 course · Ch 4 slide 13. Use the router's GigabitEthernet ports — the course configures G0/0 and G0/1 course · Ch 6 slide 29.
  2. Configure PC0 (LAN-A). IP 192.168.10.10, mask 255.255.255.0, gateway 192.168.10.1 — the gateway is R1's G0/0 address course · Ch 6 slide 31.
  3. Configure PC1 (LAN-B). IP 192.168.11.10, mask 255.255.255.0, gateway 192.168.11.1 (R1's G0/1).
  4. Enter the router configuration mode. Click R1 → CLI (or console course · Ch 2 slide 38). Follow the course steps: enable → configure terminal (abbreviated conf t) → hostname R1 course · Ch 6 slide 28.

  6. Configure and enable G0/1 (LAN-B). int g0/1 → ip add 192.168.11.1 255.255.255.0 → des Link to LAN-11 → no shut → exit → end — same transcript pattern as the course course · Ch 6 slide 29.
  7. Verify interfaces and routing table. Run show ip interface brief and show ip route — both interfaces must read up up and the table must list both LANs as C (connected) entries course · Ch 6 slide 30 course · Ch 6 slide 14.
  8. Test end-to-end and save. From PC0: ping 192.168.11.10 (and back from PC1 to 192.168.10.10). Then on R1: copy running-config startup-config to keep the work course · Ch 6 slide 30.

9Common mistakes

  • Forgetting no shutdown — the interface stays administratively down (the course shows exactly this state in its brief output course · Ch 6 slide 30).
  • Configuring the right address on the wrong interface (G0/0 and G0/1 swapped) — each address must belong to the network the interface connects course · Ch 6 slide 29.
  • Wrong PC gateway: LAN-B PCs must use 192.168.11.1, not .10.1 course · Ch 6 slide 31.
  • Mask typos on the router (255.255.0.0) — the interface and its LAN fall into different networks.
  • Testing only one direction, or only gateway pings — end-to-end means host-to-host both ways course · Ch 2 slide 38.
  • Leaving the configuration unsaved — copy running-config startup-config course · Ch 6 slide 30.

10Troubleshooting questions

Q1. PC0 cannot reach PC1. PC0's local ping to its own switch-neighbours works. What ordered checks isolate the fault fastest?

Show answer

1) ping 192.168.10.1 from PC0 (gateway reachable? if not: R1 G0/0 address/enable state — show ip interface brief course · Ch 6 slide 30). 2) Same for PC1 with 192.168.11.1. 3) On R1: are both LANs in show ip route as C entries course · Ch 6 slide 14? 4) Re-check PC gateway fields against the table course · Ch 6 slide 31. This 'local → gateway → remote' order is the course's testing-the-interface pattern course · Ch 2 slide 38.

Q2. show ip interface brief shows an interface administratively down. What caused it and what is the fix?

Show answer

The interface was never enabled — a freshly configured interface stays administratively down until no shutdown is issued course · Ch 6 slide 29; the course's brief output shows the state course · Ch 6 slide 30.

Q3. Why must PC0's gateway be 192.168.10.1 and not 192.168.11.1?

Show answer

A host's default gateway is the router interface on its own network course · Ch 6 slide 31 — for PC0 that is R1's G0/0 (192.168.10.1) course · Ch 6 slide 29. The gateway must be reachable in-layer before it can forward anywhere else.

Q4. Both router interfaces are up/up and both C routes exist, yet PC0 pings 192.168.11.10 with 0% success. What is left to check?

Show answer

PC-side settings: PC0's mask (must be 255.255.255.0) and its gateway value; PC1's address/mask/gateway against the table; then link/ARP — addresses and conflicts course · Ch 2 slide 37. Router output alone never proves end-device configuration course · Ch 2 slide 33.

9Common mistakes

10Troubleshooting questions

Q1. Fault 1 — mask. PC0 pings PC1 (192.168.10.11) fine but times out to 192.168.11.10 and to 192.168.11.1. Its mask reads 255.255.0.0. What happens inside PC0, and what is the fix?

Show answer

With /16 PC0 believes 192.168.11.0/16 is local — it ARPs for 192.168.11.10 on LAN-A instead of sending to its gateway, so remote pings die. Fix: mask 255.255.255.0 to match the plan course · Ch 2 slide 33. (Gateway tests to 192.168.11.1 also fail for this PC because that address isn't on-link.)

Q2. Fault 2 — gateway. PC1's local pings work, but every cross-network ping from it fails; its gateway field says 192.168.11.1 while PC1 is on 192.168.10.0/24. Why does this break, and what is correct?

Show answer

A gateway must be reachable on the host's OWN network first course · Ch 6 slide 31. 192.168.11.1 lives on LAN-B, so PC1 can never ARP it locally — no route out. Correct: 192.168.10.1 (R1 G0/0 course · Ch 6 slide 29).

Q3. Fault 3 — duplicate. LAN-B pings are flaky: replies come and go, and ipconfig shows PC2 = 192.168.11.10 and PC3 = 192.168.11.10. What is happening and how do you resolve it?

Show answer

Two devices answer the same address — an IP address conflict course · Ch 2 slide 37 (ARP ambiguity makes sessions flap). Fix per the plan: PC2 keeps .10, PC3 becomes 192.168.11.11 course · Ch 6 slide 31.

Q4. Fault 4 — interface addressing. show ip interface brief shows GigabitEthernet0/0 192.168.10.254 … up up but the plan says 192.168.10.1. Everything on LAN-A is configured with gateway .1. What breaks and what do you type?

Show answer

The interface's address is LAN-A's gateway — with .254 on the router and .1 configured on the PCs, no device answers ARP for the gateway, so LAN-A can't leave its network course · Ch 6 slide 31. Fix: interface g0/0 → ip address 192.168.10.1 255.255.255.0 course · Ch 6 slide 29 (address must belong to the connected network course · Ch 9 slide 4).

Q5. Fault 5 — interface not enabled. The same show output reads GigabitEthernet0/1 192.168.11.1 … administratively down down. What does that state mean and what single command clears it?

Show answer

The address is right but the interface was administratively shut — never enabled. Fix: enter the interface and issue no shutdown course · Ch 6 slide 29; expect %LINK-5-CHANGED … changed state to up course · Ch 6 slide 29 (the state itself appears in the course's brief output course · Ch 6 slide 30).
